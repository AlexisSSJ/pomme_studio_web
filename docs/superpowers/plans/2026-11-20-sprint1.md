# Sprint 1 — Usuarios, RBAC, Administración y Auditoría

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar los modelos de datos, autenticación, control de acceso por rol/proyecto, endpoints de administración `SUPER_ADMIN` con auditoría, UI mobile-first y pruebas `pytest` del Sprint 1.

**Architecture:** Backend FastAPI + SQLAlchemy 2.0 async + Alembic sobre PostgreSQL (SQLite async en tests). Frontend Next.js 14 App Router con Tailwind *Tactile Brutalism*. JWT para auth; dependencias reutilizables para kill switch, roles y membresía de proyecto. Toda acción crítica de administración se registra en `audit_logs`.

**Tech Stack:** Python 3.12+, FastAPI, SQLAlchemy 2.0 async, Alembic, asyncpg, aiosqlite (tests), python-jose, passlib[bcrypt], Pydantic 2; Next.js 14, TypeScript, Tailwind CSS.

**Spec:** Solicitud del usuario + `AGENTS.md` + `docs/architecture.md`.

## Global Constraints

- Roles válidos: `SUPER_ADMIN`, `LEAD_DESIGNER`, `COLLABORATOR`, `CLIENT`.
- El estudio vende **solo** diseño, dirección creativa, documentación ejecutiva y especificaciones FF&E. Nada de obra, montaje, inventario, compras de construcción ni cuadrillas.
- Paleta *Tactile Brutalism*: `#F7F7F5`, `#111111`, `#EFECE6`. Prohibido `box-shadow`, degradados y colores saturados.
- `border-radius: 0px`; bordes `1px solid #111111`; grids `gap: 1px` sobre fondo `#111111` con celdas `#F7F7F5`.
- Mobile-first (`375px`+), grids colapsan a `1fr`, áreas táctiles `44px × 44px`.
- Todo endpoint protegido valida en orden: autenticación (`401`), `is_active == True` (`403`), rol permitido (`403`), membresía/propiedad de `project_id` (`403`/`404`).
- Cambios de esquema **siempre** vía Alembic; prohibido `create_all()` en producción.
- `pytest tests/backend -v` debe pasar antes de integrar.

## Review Focus

- Token válido pero usuario desactivado → `403` inmediato (kill switch), incluso si el token no expiró.
- `CLIENT` o `COLLABORATOR` intentando endpoints de `SUPER_ADMIN` → `403`.
- Usuario sin membresía en `project_id` → `403`/`404` sin filtrar existencia del recurso.
- Cambio de rol / activación / desactivación / edición de pricing sin registro en `audit_logs` → fallo de auditoría.
- Payloads con campos desconocidos o contraseñas débiles → rechazo `422`.
