# Sprint 4 — Etapas, Entregables, Pines, Rondas y Reuniones de Proyecto — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregables versionados por etapa con candado secuencial, pines táctiles, control de rondas de cambio y reuniones de revisión/levantamiento en Google Calendar, con auditoría completa y portal mobile-first.

**Architecture:** FastAPI async + SQLAlchemy 2.0 sobre el patrón existente de Sprint 3 (endpoints delgados con guards en `api/deps.py`, auditoría vía `services/audit.log_audit`, storage local autenticado). El candado de etapas y las rondas viven en la lógica de endpoints; el scheduling reutiliza `services/scheduling.py` y `GoogleCalendarClient`. Frontend Next.js 14 App Router con componentes compartidos (visor y scheduler) usados por portal y admin.

**Tech Stack:** Python 3.12+ / FastAPI / SQLAlchemy async / Alembic / Pydantic 2 / pytest + pytest-asyncio (SQLite in-memory) / Next.js 14 + TypeScript + Tailwind.

**Spec:** `docs/superpowers/plans/2026-11-21-sprint4-brief.md` (verbatim del usuario) + `AGENTS.md` + `docs/architecture.md`.

## Global Constraints

- Roles válidos: `SUPER_ADMIN`, `LEAD_DESIGNER`, `COLLABORATOR`, `CLIENT`. Todo endpoint protegido valida en orden: autenticación (401), `is_active` (403 "Inactive user"), rol (403 "Insufficient permissions"), membresía (403 "No access to this project").
- Escrituras de proyecto exigen `project.status == ACTIVE`; si no → 409 `"Project is not active"` (helper existente `require_active_project`).
- Aislamiento por ítem: toda consulta de recurso anidado filtra `id == resource_id AND project_id == path project_id`; id de otro proyecto → 404 (sin fuga de existencia).
- Toda tabla nueva requiere migración Alembic (`backend/alembic/versions/0005_…`, revision `"0005"`, down_revision `"0004"`); prohibido `create_all()` en producción.
- Acciones sensibles → `log_audit(db, actor_user_id=…, action=…, entity_type=…, entity_id=…, metadata={… "project_id": str(project_id) …})`.
- Uploads: 10 MiB → 413 `"File exceeds the 10 MiB limit"`; tipo no permitido → 422 `"Unsupported file type"`; clave `<project_id>/<uuid_hex><ext>` vía `LocalStorage`; descarga solo por endpoint `/file` autenticado.
- Calendar: `CalendarNotConnectedError` → 503 `"Calendar integration not connected"`; `CalendarAPIError` → 502 `"Calendar provider unavailable"`; `SlotUnavailableError` → 409 `"Slot no longer available"`; `ValueError` de validación → 422 con `str(exc)`. Reserva local `scheduled` antes del evento remoto; fallo de Google elimina la reserva; fallo del commit de confirmación borra evento + reserva. Nunca exponer `GOOGLE_REFRESH_TOKEN`.
- `meetings`: exactamente un padre (`project_id` aquí, `lead_id=None`); `end_time > start_time`; times persistidos en UTC aware.
- Enums nuevos SQLAlchemy: `SAEnum(..., native_enum=False, values_callable=lambda members: [m.value for m in members])` con valores lowercase y `server_default` lowercase (patrón `MeetingStatus`).
- UI: paleta `#F7F7F5`/`#111111`/`#EFECE6`; `border-radius: 0`; bordes `1px solid #111111`; retículas `gap: 1px` sobre fondo `#111111` (clases existentes `grid-brutal`, `btn-brutal`, `label-mono`); sin `box-shadow` ni degradados; áreas táctiles ≥ 44×44px; mobile-first 375px; ninguna función crítica depende de `hover`; textos de UI en español.
- Sin módulos de ejecución de obra, montaje, inventario, compras ni cuadrillas.
- Verificación backend: `backend/.venv/bin/python -m pytest tests/backend -q` desde la raíz del repo (venv symlinked; Python 3.14 local, código compatible 3.12). Verificación frontend: `npm run build` en `frontend/` (typecheck + lint; no hay infra de tests unitarios frontend).
- Commits frecuentes por tarea; mensajes en estilo del repo (`feat(backend): …`, `feat(frontend): …`, `test(backend): …`).

## Review Focus

1. **Carrera de decremento de rondas:** dos `request-changes` concurrentes no deben llevar `remaining_rounds` a negativo. Test secuencial que agota rondas verifica piso en 0 (Task 4); la carrera extrema se documenta como hardening pendiente (Task 7), igual que Sprint 3 hizo con el upsert de reacciones.
2. **Desbloqueo fuera de orden:** aprobar una etapa debe desbloquear la siguiente por `order_index` aunque las etapas se hayan creado en orden distinto (Task 2, test con creación 0,2,1).
3. **Coordenadas de pin bajo zoom:** el % del pin se calcula contra `getBoundingClientRect()` de la imagen (que refleja el scale), no contra el contenedor sin transformar (Task 6; revisión de la matemática en el diff).
4. **Fuga cross-project en recursos anidados:** stage, deliverable, comment y `stage_id` de reunión de otro proyecto → 404 en todos los endpoints nuevos (Tasks 2–5, un test por recurso).
5. **Compensación de reserva de reunión:** fallo de Google tras reservar no deja reunión huérfana ni evento sin reserva (Task 5, test con cliente falso que falla tras observar la reserva).
