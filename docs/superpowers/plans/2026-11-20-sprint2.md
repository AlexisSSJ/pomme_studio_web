# Sprint 2 — Leads, Proyectos, Cotizador y Google Calendar

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Captar leads con diagnóstico desde el front-office, agendar Discovery Calls con disponibilidad real de Google Calendar (freebusy + Meet), cotizar con `pricing_config`, convertir leads en proyectos y activarlos al marcar el anticipo pagado.

**Architecture:** Backend FastAPI + SQLAlchemy 2.0 async + Alembic (PostgreSQL en producción, SQLite async en tests). Servicio `GoogleCalendarClient` (httpx) con refresh_token OAuth, freebusy y creación de eventos con Meet; la lógica de slots es pura y testeable. Frontend Next.js 14 App Router, *Tactile Brutalism*, mobile-first. Toda acción sensible se registra en `audit_logs`.

**Tech Stack:** Python 3.12+, FastAPI, SQLAlchemy 2.0 async, Alembic, httpx, Pydantic 2, pytest + pytest-asyncio + aiosqlite; Next.js 14, TypeScript strict, Tailwind CSS.

**Spec:** Solicitud del usuario (Sprint 2) + `AGENTS.md` + `docs/architecture.md`.

## Global Constraints

- Roles válidos: `SUPER_ADMIN`, `LEAD_DESIGNER`, `COLLABORATOR`, `CLIENT`.
- El estudio vende **solo** diseño, dirección creativa, documentación ejecutiva y especificaciones FF&E. Nada de obra, montaje, inventario, compras de construcción ni cuadrillas.
- Todo endpoint protegido valida en orden: autenticación (`401`), `is_active == True` (`403`), rol permitido (`403`), membresía/propiedad de `project_id` cuando aplique (`403`/`404`).
- Paleta *Tactile Brutalism*: `#F7F7F5` fondo/celdas, `#111111` tinta/bordes, `#EFECE6` superficie. Prohibido `box-shadow`, degradados y colores saturados.
- `border-radius: 0px`; bordes `1px solid #111111`; grids `gap: 1px` sobre fondo `#111111` con celdas `#F7F7F5` (clases existentes `grid-brutal`, `label-mono`, `btn-brutal` en `globals.css`).
- Numeraciones `01`–`04` en mayúsculas monospace 11px (`label-mono`); botones con flecha `↗` que invierten colores en `:hover`.
- Mobile-first (`375px`+): grids colapsan a `1fr` conservando `gap: 1px`; áreas táctiles mínimas `44px × 44px`; ninguna función crítica depende de `hover`.
- Cambios de esquema **siempre** vía Alembic; UUID PK; `created_at`/`updated_at` UTC; enums con `native_enum=False` (compatibilidad SQLite tests).
- Dinero siempre `Decimal` / `Numeric(12,2)`; totales cuantizados a `0.01` con `ROUND_HALF_UP`.
- Google: consultar `freebusy` antes de proponer horarios; **verificación final** antes de crear el evento; `conferenceDataVersion=1` + `hangoutsMeet`; si la creación falla, la reunión NO se persiste como confirmada; el `refresh_token` nunca aparece en respuestas API ni en mensajes de error.
- Acciones sensibles (crear lead, agendar reunión, propuesta, conversión, activación) se registran en `audit_logs` vía `app/services/audit.py::log_audit`.
- `pytest tests/backend -v` debe pasar antes de integrar. Comando: `backend/.venv/bin/python -m pytest tests/backend -v` desde la raíz del repo.
- Frontend: TypeScript strict sin `any` implícitos; verificar con `cd frontend && npx tsc --noEmit && npm run build`.

## Review Focus

- Doble reserva del mismo slot (carrera o reintento) → la segunda debe fallar `409` por la verificación final freebusy + solape local, sin crear evento duplicado.
- Conversión de lead sin `pricing_config` → `409` sin crear proyecto y sin cambiar el estado del lead.
- Fallo de la API de Google al crear el evento → no queda fila `meetings` confirmada (consistencia Google↔BD).
- `CLIENT`/`COLLABORATOR` en endpoints internos de cotización/conversión/activación → `403`; admin desactivado → `403` inmediato.
- Horarios fuera de horas hábiles, desalineados de la retícula de 30 min o en el pasado → `422` sin llamar a Google.
- `refresh_token` filtrado en respuestas o detalles de error → fallo de seguridad.

**Interfaces:**
- Consumes: `Settings` de `app/core/config.py`.
- Produces (usado por Task 3):
  - `class CalendarNotConnectedError(Exception)` — sin `GOOGLE_REFRESH_TOKEN`.
  - `class CalendarAPIError(Exception)` — fallo HTTP/respuesta inválida de Google.
  - `@dataclass(frozen=True) class BusyInterval: start: datetime; end: datetime` (aware UTC).
  - `@dataclass(frozen=True) class CalendarEvent: event_id: str; meet_link: str`.
  - `class GoogleCalendarClient(settings: Settings, transport: httpx.AsyncBaseTransport | None = None)` con:
    - `async freebusy(start: datetime, end: datetime) -> list[BusyInterval]`
    - `async create_meet_event(summary: str, start: datetime, end: datetime, attendee_email: str) -> CalendarEvent`
  - `def compute_available_slots(busy: list[BusyInterval], window_start: datetime, window_end: datetime, duration: timedelta, step: timedelta | None = None) -> list[tuple[datetime, datetime]]` — pura; `step` default = `duration`.

**Settings nuevos** (defaults exactos, añadir también a `.env.example` con comentarios en el estilo existente):
- `GOOGLE_REFRESH_TOKEN: str = ""` (vacío = integración desconectada; nunca se expone en API).
- `STUDIO_TIMEZONE: str = "America/Mexico_City"`
- `STUDIO_BUSINESS_START: str = "09:00"`
- `STUDIO_BUSINESS_END: str = "18:00"`
- `DISCOVERY_CALL_MINUTES: int = 30`

**Comportamiento del cliente:**
- `_get_access_token()`: POST `https://oauth2.googleapis.com/token` con `grant_type=refresh_token`, `refresh_token`, `client_id`, `client_secret` (form-encoded). Si `GOOGLE_REFRESH_TOKEN == ""` → `CalendarNotConnectedError` **antes** de cualquier llamada. Respuesta no-2xx o sin `access_token` → `CalendarAPIError` con mensaje genérico (sin secretos).
- `freebusy`: POST `https://www.googleapis.com/calendar/v3/freeBusy` con body `{"timeMin": start.isoformat(), "timeMax": end.isoformat(), "timeZone": "UTC", "items": [{"id": settings.GOOGLE_CALENDAR_ID}]}` y header Bearer. Parsea `calendars[calendar_id].busy` → `BusyInterval` (datetimes aware UTC).
- `create_meet_event`: POST `https://www.googleapis.com/calendar/v3/calendars/{calendar_id}/events` con query `conferenceDataVersion=1` y body `{summary, start: {"dateTime": iso, "timeZone": "UTC"}, end: {...}, attendees: [{"email": attendee_email}], conferenceData: {"createRequest": {"requestId": str(uuid4()), "conferenceSolutionKey": {"type": "hangoutsMeet"}}}}`. Extrae `id` y de `conferenceData.entryPoints` el que tenga `entryPointType == "video"` → `meet_link`. Sin link o sin id → `CalendarAPIError`.
- Todas las llamadas usan `httpx.AsyncClient(transport=self._transport, timeout=10.0)`; el transporte inyectable permite `httpx.MockTransport` en tests. HTTP ≥ 400 → `CalendarAPIError`.
- `compute_available_slots`: genera candidatos desde `window_start` avanzando `step` mientras `candidate + duration <= window_end`; descarta los que solapan algún `BusyInterval` (solape estricto: `candidate < busy.end and candidate + duration > busy.start`; adyacencia exacta NO es solape). Devuelve pares `(start, end)` aware.
